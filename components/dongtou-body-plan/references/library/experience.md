# 经历讲法：把真实经历讲成对读者有用的内容

先确认本篇有谁的经历、允许怎样归因；参考作者的自述不能换成“我”。东头真实素材可以来自用户明确提供的文本、录音转写或本篇既有材料，不去无关个人目录寻找故事。

| 经历讲法 | 需要的真实材料 | 参考 |
|---|---|---|
| 原来不懂/不敢→具体尝试→发现新手卡点→方法 | 起点、真实动作、变化；没有结果就不写结果 | [05](cards/sample-05.md) |
| 某个态度导致问题→换视角→改动作→读者可用判断 | 具体事件，保留本人判断与其他可能解释 | [21](cards/sample-21.md) |
| 一次选择→遇到的困惑→如何理解→现在建议 | 真实选择与感受，不把个人路径写成所有人的必经阶段 | [04](cards/sample-04.md) |
| 任务/测试→操作→几次修改→结果→适用条件 | 本篇可查过程或成品；来源测试保持归因 | [11](cards/sample-11.md)、[09](cards/sample-09.md) |
| 两个事件→分别获得什么认识→共有判断 | 两个真实事件，不移植收入、礼物和商业结论 | [18](cards/sample-18.md) |
| 发现自己问题→看见他人也需要→解决→方法沉淀 | 自己的需求、证据、行动；同一故事复述不增权 | [23](cards/sample-23.md)、[24](cards/sample-24.md) |

只放能解释当篇问题的经历。通用工具介绍可以完全不带个人故事；缺经历但标题承诺亲测时明确待补或回第三步调整，不能编一段“我也踩过”。若用户提供只有感受，不擅自补客户、日期或数字。

经历功能要落到正文：它证明什么、说明什么局限、读者如何迁移。个人故事带来的信任和传播效果是待验证判断，不预设必然提高数据。参考稿的课程引流、身份与训斥语气按本篇需要决定，不自动采用。

## 新增33篇公众号：我的判断怎样从经历里长出来

先用下表定位需要，再回读卡和原稿。只借组织方法，观点仍由东头形成；不要搬原作者成绩或口吻。

| 参考 | 观察到的动作 | 可迁移到本篇 |
|---|---|---|
| [26 贡献与收入错位的系统解释](cards/sample-26.md) | 动作和旧信念之后写后来发现，让经历承担观点来源。 | 询问东头当时想法、实际反馈和现在建议。 |

| [28 两段职场经历推到个人节点](cards/sample-28.md) | 对照规模、反馈、审批，让经历支持具体判断。 | 从东头真实协作体验中提取同维度对照。 |
| [29 从识别高手到拆出方法](cards/sample-29.md) | 用持续调整呈现学习过程，弱化天赋神话。 | 讲东头真实参考、调整、测试某一写作方法的过程。 |
| [30 个体业务趋势与三种内容杠杆](cards/sample-30.md) | 经历里说明我和工具各自做什么，使第一人称承担判断。 | 写东头在七步流程里真正提供的观点与检查动作。 |
| [31 输出数量转向读者与目的](cards/sample-31.md) | 明确内容中的经验和主观观点来自我，突出作者位置。 | 写我的观察、我的判断、我为什么这样建议。 |

| [36 从独自硬扛到SOP和AI分工](cards/sample-36.md) | 旧动作、代价、改法有时间顺序，第一人称解释决策。 | 讲东头七步套件的真实建设动机和可见调整。 |
| [37 新手公众号起步与变现菜单](cards/sample-37.md) | 将个人报价作为具体例子并随后说明未实际合作。 | 讲自己的决策、结果和未发生的部分，避免把报价说成到账。 |
| [38 把争论转成信息应用](cards/sample-38.md) | 以前争辩—现在赶路的对照给出观点变化。 | 讲自己的旧习惯、转折理由与如今判断。 |
| [39 从功能到目标身份的桥梁](cards/sample-39.md) | 围绕年度任务组织多次投入的判断。 | 讲清自己的任务、投入标准、过程收获与限制。 |
