# 两份主要交付

## 修订文案.md

完整、连贯、可以单独阅读的文章，保留锁定文本；默认另存，不覆盖原稿。只检查时交付原文完整副本或清晰的原文件链接，不声称修订。存在关键缺料时仍提供当前完整稿，出厂状态写在报告里，不把它描述为合格。

## 质检报告.md

开头写结论、对应的文案文件和当前全文 SHA-256，然后依次包括：

1. 本篇约定：读者、问题、承诺、固定项、允许修改范围、文风、结构，及作者视角方式、我的核心观点、理由、建议、观点来源与状态。继承、授权代拟与用户确认分清。
2. 五项检查：状态、具体位置、当前正文引句及理由；可信性附对应来源位置，兑现附承诺→答案。
3. 结构验收：每个采用阶段→具体正文位置、功能、材料、衔接、结论；缺失也列出来。
4. 至少六轮记录：重点、所读版本指纹、实际发现、处理；最后完整终检复验五项。
5. 修改与缺口：实际改了什么；哪里仍未通过；需要什么具体材料/决定及回到哪一步。

内容务求具体，不使用“总体不错、六轮全部通过”代替证据。检查报告不等于真实读者或发布验证。

另列“作者视角验收”：状态、当前正文引句、核心观点如何被理由与案例说明、建议如何接住立场。失败不能判可交稿。明确客观体裁或受限第三人称范围时，记录用户要求及不适用理由；旧稿缺失观点记录不虚造原来的确认。

## 内部记录格式

保存 `.review/receipt.json`。用文件真实 UTF-8 字节计算 SHA-256；每轮指纹来自实际检查版本，不能在事后把旧稿检查记成新稿检查。

```json
{
  "final_sha256": "实际当前文件的64位小写十六进制指纹",
  "verdict": "可交稿",
  "rounds": [
    {"round": 1, "focus": "want_read", "reviewed_sha256": "实际版本指纹", "findings": ["实际发现和位置"], "actions": ["修改或保留理由"]}
  ],
  "final_checks": {
    "want_read": {"status": "通过", "article_quotes": ["当前正文中原样出现的引句"], "reason": "为何足够"},
    "understandable": {"status": "通过", "article_quotes": ["当前正文引句"], "reason": "理由"},
    "credible": {"status": "通过", "article_quotes": ["当前正文引句"], "reason": "理由及来源"},
    "fulfilled": {"status": "通过", "article_quotes": ["当前正文引句"], "reason": "承诺兑现位置"},
    "structure": {"status": "通过", "article_quotes": ["当前正文引句"], "reason": "约定阶段如何完成"}
  },
  "author_view": {
    "required": true,
    "mode": "直接代写",
    "core_view": "本篇实际采用的我的核心观点",
    "viewpoint_source": "授权代拟",
    "viewpoint_status": "试稿可调整",
    "status": "通过",
    "article_quotes": ["当前正文中表达观点、理由或建议的准确引句"],
    "reason": "具体说明材料如何支持我的观点、建议如何延续它"
  }
}
```

示例仅展示字段，实际 `rounds` 至少六项，按顺序连续编号；前五轮依次为五个检查键，第六轮为 `full`。如继续修订和检查，最终轮也必须是 `full`，并指向最新文案指纹。

通过项必须提供当前正文准确引句；缺失项可以不含引句，但必须有具体缺口理由。新版执行必须保存 author_view 对象，并用 --require-author-view 检查；五项 final_checks 键保持原样。明确客观体裁时 required 为 false、status 为“不适用”，reason 写实际用户要求，core_view 可空，mode 写实际体裁；不能仅为绕过失败改成不适用。

历史记录缺 author_view 时可不加新参数检查旧格式一致性，结果不等于满足新版作者视角规则。脚本只检查记录、指纹、次数/顺序、准确引句及结论一致性；不能证明实际审阅、作者感、结构语义或来源属实。这些仍要按正文和材料判断。

## 活人感表达复核

新版在同一质检报告单列实际 human-writing 版本/入口、材料与说话位置依据、主要表达修改、全文与可编辑范围原始检查结果、语境提醒的人工判断及保护冲突。内部 receipt 增加 human_writing，按 human-writing-receipt.md 填真实状态，并用 --require-human-writing 检查记录；final_checks 五个键与作者视角记录保持原样。范围受限不能写成原包全文通过，材料不足或可编辑部分未通过不能判可交稿。
