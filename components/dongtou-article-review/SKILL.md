# 东头文案出厂质检

接住第六步修订稿，检查“想不想看、能不能看懂、凭什么相信、有没有兑现、有没有遵守选定结构”。逐项找正文证据，在允许范围内修订；文字顺畅不能替代依据和承诺兑现。

## 1. 接住初稿和要求

先读 [交接规则](references/handoff.md)，完整读取当前文章、第六步改稿记录、第五步写作记录、讲法卡或结构约定，再读取与本篇判断有关的来源。接住已定的方向、读者、标题、开头、文风和结构，标明哪些可以改、哪些必须保留。

支持两种输入：第六步完整交接；用户已有正文直接检查。已有记录可以作为约定来源，缺少的信息写明“待确认”，不要为了凑齐文件重跑前六步，也不要因为一项缺失就放弃其他可做的检查。

## 2. 五项检查，保留三层标准

读 [质检标准](references/standards.md)。五项都必须检查；每一项同时对照清单、正文及来源证据、本篇约定。不得用总分把某一项失败抵消。

本篇约定还必须验收作者视角：接住“作者视角方式、我的核心观点、为什么这样看、给读者的建议、观点来源与状态”，查正文是否让读者知道东头怎么看、理由是什么，以及案例和建议如何支持这条立场。只在摘要里加几次“我认为”不算通过；没有亲历仍可用第一人称表达观点，不能编个人经历。授权代拟可交试稿，不要求观点逐条确认。作者视角失败时不能判可交稿；用户明确客观报告或受保护的第三人称范围则记录不适用的依据。

结构检查读 [结构验收方法](references/structure.md)，从 [58篇索引](references/library/index.json) 找到本篇采用的卡，实际读取卡与原文。验收采用的各阶段功能、材料和衔接；只出现相同小标题不算通过。不擅自删除约定或把原本必需的阶段降为可选。41、54只作局部参考；先核对索引的完整性与采用范围，未收到的阶段不能当已知结构。

## 活人感复核

完整读内置 [human-writing](../human-writing/SKILL.md) 与初稿后使用的 revision，核对第五步实际读取和改稿记录，按 [套件接入规则](../../references/human-writing-integration.md) 复验当前稿。作者说话位置、材料、语序节奏与结尾分别纳入已有五项和作者视角检查，不另增写手或固定工序。材料不足、假亲历和重复注水仍阻止交稿。

保存原包全文脚本结果；用户保护项命中时列具体冲突和依据，仅对可编辑范围继续修改与检查，不擅改标题/开头/结构，也不称全文通过。语境提醒人工判断。新增采用记录格式见 [活人感回执](references/human-writing-receipt.md)。

## 3. 至少六轮，边检查边修

按 [六轮流程](references/rounds.md) 执行：前五轮分别集中检查五项，第六轮完整重读当前全文并复验五项。每轮记录具体发现、位置、处理和所读版本；没有发现问题也写清检查了什么、为何保留。

可以修解释、冗余、过渡、例子标识，以及来源已支持的回答；遵守用户的改动范围。发现锁定的承诺无法兑现，回第三步处理标题或补料；选定结构本身需要调整，回第四步。不得暗中重选题、换结构或捏造东头的经历、测试、收入、数据。

缺材料、事实待核验或越过改动范围的阻碍，列明具体缺口和下一动作。需要核验时只查与本文关键判断有关的来源。六轮后仍未解决的项目保留失败或待核验状态，不假装通过，也不无限空转。

## 4. 交付和校验

按 [输出规范](references/output.md) 交付两份主要文件：

- `修订文案.md`：完整正文；默认另存，不覆盖原稿。
- `质检报告.md`：结论、五项正文证据、结构逐阶段映射、至少六轮记录、修改和剩余缺口。

内部生成 `.review/receipt.json`，记录版本指纹和最终引句，并运行：

```text
python3 scripts/review_receipt.py --article <修订文案路径> --receipt <记录路径> --require-author-view --require-human-writing
```

脚本只检查记录结构、版本和正文引句一致性，不证明作者感、内容质量、事实真实性或实际读者效果。报告必须区分“可交稿、退修、待补材料、待核验”；只有最新全文五项及适用的作者视角约定都通过、活人感表达复核通过或按明确保护范围受限、检查次数足够、没有关键缺口，才可交稿。历史回执可以不用新参数核对原一致性，但不能冒称已通过新版作者视角或活人感要求。

用户要求“只检查”时不改文案；要求“只改某段”时只改该段，其他发现写报告。无论结论如何，本 Skill 不发布、不写公众号草稿箱、不发送消息、不更新前六步 Skill 或总控。

## 调用示例

“用 $dongtou-article-review 检查这篇初稿，沿用我的讲法卡，至少六轮，交付修订文案和质检报告。”

“用 $dongtou-article-review 只修改第三段；全文问题照常报告，标题和开头保持原样。”

方法依据：用户确定的五项出厂要求、清单/证据/本篇约定三层标准，以及58篇用户提供的文稿（含局部材料）。参考文稿的结构是可验收的材料，不是爆款保证。
