# 东头创作总控

这是八个组件中的创作总控，负责衔接七道工序。创作主链为 **1→2→3A→4→5→6→7**，结束于**完整文案＋质检报告**。第六步独立做活人感改稿，第七步负责最终出厂质检。

## 本轮范围与选择

- **完整创作：**明确要从素材完成文章或运行完整总控时，按 [执行流程](references/workflow.md) 接续七步。默认在原主题、账号定位与材料边界内代选推荐的方向、标题和讲法，标“总控代选”并记依据，不能写“用户已确认”。用户指定方向、标题或要求先看候选/自己选时优先遵从。
- **已有产物续做：**完整读当前文件，从最早实际缺口开始。按 [交接与状态](references/handoff-state.md) 分清本轮执行、沿用、待补和未执行；文件名不同不重做，已有选择不重选。
- **现稿局部修改／只检查：**按请求进入第三步B、第五步、第六步或第七步，保护其余文字。缺前五步报告也能处理自己的现稿，不能补造全流程经历。
- **只要某一步、蓝图、诊断或讨论：**只做指定工作。纯链接或“读一下”不自动授权全文创作。

最新要求、固定标题/开头、已选方向、真实依据和修改范围优先。代选不扩大原主题、不加无依据的效果承诺或经历。关键缺口影响方向或事实才聚焦询问，同时继续不依赖回答的工作；已授权阶段不重问是否开始。

## 作者视角与两种方式

完整创作从第二步起默认进入东头第一人称视角，按 [作者视角](references/author-view.md) 选择对话共创或直接代写。用户要求先聊，就直接在对话中问缺失的“我想表达什么、为什么、建议什么”；其余完整创作默认直接代写，在材料支持范围内组织作者判断并写试稿，不逐条等待观点确认。

一路传递“作者视角方式、我的核心观点、为什么这样看、给读者的建议、观点来源与状态”。授权代拟与用户原话/已确认分开记录；授权代拟可继续写第一人称试稿，不能被误记成阻断创作的待确认，也不在正文每段贴状态标签。没有东头亲历仍可以表达明确判断；原作者经历不转成东头事实。明确客观报告、固定第三人称和局部范围优先。

## 实际入口与执行

此副本是完整套件的内置总控。七步核心入口只从同级 `components/` 读取，不能调到同名独立旧版；内置入口缺失就报告缺口。完整流程读 [执行流程](references/workflow.md) 和 [分工表](references/skill-map.md)。每一步用前完整读它的实际 SKILL.md 及要求的相关参考，传清范围、输入、保护项、选择状态、输出目录和总控接续。遵循规范并生成实际产物才算执行，列计划、找到文件或代理说完成都不算。

```sh
python3 <本Skill目录>/scripts/resolve_assets.py
```

脚本只读定位 [七步依赖](references/dependencies.json)，支持 `--from-step N` 或 `--only-step N` 检查实际所需入口，沿用 `--project-root`、`--skill-root`、`--catalog`。可读不等于样本已读或版本语义兼容。缺入口就说明未完成部分，不自行安装或换旧模块冒称执行新版流程。

文风目录 [dna-catalog.json](references/dna-catalog.json) 供第四步发现候选，匹配和实际读样本交第四步；需要该目录时再读 [匹配补充](references/matching.md)。不在第三步前插入旧文风步骤。

## 七步的交接

| 步骤 | 入口 | 交给下一步 |
|---|---|---|
| 1 完整读取 | dongtou-source-reader | 完整读取记录＋速读卡，两份独立文件；底稿与事实状态 |
| 2 找切入点 | dongtou-angle-finder | 切入点卡＋分析记录；读者、方向及我的观点、理由、建议和来源状态 |
| 3 标题开头 | dongtou-title-opening | A：体现本人发现/判断的标题、开头、问题与承诺；自己的全文按需B |
| 4 正文讲法 | dongtou-body-plan | 一个主文风、主结构；安排我的观点如何被材料说明，附第一人称短示范 |
| 5 完整成稿 | dongtou-article-writer | 完整初稿＋写作记录，第一人称作者判断贯穿主线 |
| 6 活人感改稿 | human-writing | 活人感修订稿＋改稿记录，保留我的观点、既定结构与事实边界 |
| 7 出厂质检 | dongtou-article-review | 完整修订文案＋质检报告，五项及作者视角约定分别验收 |

第一步独立默认与本项目不同，新执行时明确要**两份文件**。已有充分详细记录缺卡，可以据记录补卡并记继承，不假称重新开原文。第三步A的参考作者全文不能当东头自己的全文B。

第五步后仅在确需优化标题开头/检查其实际兑现时进入第三步B，不机械多跑；改稿后接6→7。第四步实际读文风与参考，第七步按58篇库验收采用功能，保留清单、证据、本篇约定三层标准。

五项必须分别检查：**想不想看、能不能看懂、凭什么相信、有没有兑现、是否遵守结构**。至少六轮，最后重读当前完整稿。不能用总分、脚本通过、万赞样本或泛泛的“六轮通过”替代依据和实际审阅。

作者视角属于本篇约定必查项：当前正文是否表达我的核心判断及理由，来源案例是否服务于它，建议是否延续同一立场。缺失时不能只凭原五项的机械记录判“可交稿”。不计第一人称词频，不要求每段同一句式；用户指定客观体裁则准确记录不适用及原因。

## 第六步活人感改稿

第五步开稿前读同级 human-writing 的 SKILL、forum-prose、reality，先核具体材料与说话位置，再由原写手成稿。第六步完整读取初稿和写作记录，再读取 revision 集中改表达，保存修订稿、改稿记录和范围检查结果。第七步检查改完的全文，原五项/三层/至少六轮仍有效。遵守 [接入规则](../../references/human-writing-integration.md)，保护已定观点、固定标题开头、结构、DNA 与修改范围。第六步是独立改稿工序，接住第五步结果，不重启选题、不替代第四步主文风，不重新写成另一篇文章。

内置入口与完整文件缺失就报缺口；独立安装保留但不作为回退。保护文字触发原包禁令时列准确文字和用户依据，记录可编辑范围结果，不能声称全文通过。没有具体材料时先补料或按权限缩短，固定承诺仍待补。

## 定向返修与结束

原意/事实→1；方向/读者→2；标题开头承诺→3；主文风/结构→4；正文解释衔接→5或6允许的本地修订。只更新受影响后续产物，未变部分保留。相同问题无新材料/许可修后仍不成立，就交具体缺口，以退修/待补/待核验结束，不无限循环。

锁定标题或开头缺依据时保留原字，指出所需材料或改动许可；不降低正文承诺以宣布通过。局部修改后可报告其他问题，不能越过范围改全文。

直接交第七步**完整修订文案与质检报告**，回读文件，核对当前全文与终检版本。使用第七步内部回执时运行：

```sh
python3 <本Skill目录>/scripts/verify_delivery.py --article <当前文案> --report <质检报告> --receipt <第七步回执> --require-author-view --require-human-writing
```

脚本只查文件与记录一致性，不能证明实际六轮、作者感、事实或结构语义。新版执行要求作者视角及活人感记录；旧回执可不加新参数检查历史一致性，但不据此称它通过新版作者视角或活人感要求。旧稿无回执不编造，必要时交7复检。优先呈现完整文案与报告真实链接；中间文件和 [总控记录](assets/writing-record.md) 供回查，不要求用户填表。部分稿/未通过据实说明，流程结束不等于文案通过。

终检后不再通篇清理、另拟标题或改正文；文字改动须补受影响检查和当前全文终检。不新增确认定稿、配图、排版、草稿箱、发布、复盘或下一篇节点。用户另提这些需求视为另一任务。
