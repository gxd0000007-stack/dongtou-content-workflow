# 第一、二步如何交到第三步

只在承接前两步或处理交接冲突时读取。交接由 Codex 读取上一步产物并执行本步规则完成，不是 Skill 文件自己自动运行。

## 第一部的来源依据

本项目已要求 **完整读取记录＋速读卡**；底稿或原文件独立保留。承接至少包含：

- 来源身份、实际读取范围与缺口、原文或底稿位置。
- 核心观点及其出处、对应依据、作者明说或根据全文归纳。
- 事实状态、限定条件、外部待核验项。

速读卡用于定位，完整记录用于判断材料能说明什么。有冲突就回查详细记录和原始位置，不拼成新的作者结论，不把继承报告写成“本轮重新打开原网页”。

兼容安装中的第一步将详细内容命名为 `阅读拆解.md` 等情况：按内容识别，不要求用户为本步重做相同报告。只有详细记录缺少速读卡、但关键依据足够时继续，注明输入状态。缺少足以影响标题承诺的内容才补读；原文没提供的新证据列待补或按当篇需要调研，重复读取不能补出不存在的依据。

## 第二步的已选方向

读取切入点卡与分析记录，接住以下信息：

| 项目 | 本步用途 |
|---|---|
| 选择状态与方向 ID | 待选择、用户已选或授权代选；推荐不等于选定 |
| 作者视角方式 | 对话共创或直接代写；依当前授权接续，不为代拟观点重复设确认关卡 |
| 我的核心观点、为什么这样看、给读者的建议 | 标题、开头和正文路线围绕同一份作者观点，不只摘要原文 |
| 观点来源与状态 | 用户原话、用户确认或授权代拟／试稿，以及材料位置；代选入口不等于确认观点 |
| 原文主题与采用范围 | 保留全文或局部的边界 |
| 当篇读者及解释起点 | 沿用已知前提，知道哪些词要解释 |
| 内容目的与阅读理由 | 学习、了解消息、判断、尝试等，不限定痛点 |
| 已选入口、用户固定标题 | 限定表达方向，固定标题逐字保留 |
| 阅读收益与场景安排 | 场景可作入口、例子或条件，不强制改为任务教程 |
| 依据位置与事实状态 | 把每项承诺接到真正的材料 |
| 东头已有贡献、待补项、其他要求 | 不编亲历，不掩盖缺口 |
| 上游文件路径与版本 | 回查与保存使用同一篇材料 |

已选且没有重新比较请求时，本步不重选人群、不扩散新的选题。若待选择，明确留在待选状态；用户指定候选试做就仅为该候选设计，不宣布其已定稿。收到明确代选授权才选择，并记录依据。

C0 保留原文主题／入口，不能替代我的作者视角。旧版交接缺少作者视角字段但信息足够时，按本轮方式补足：先聊就仅问缺失关键，完整创作授权就直接组织有依据的第一人称试稿。记录补充发生在本步，不伪造上游完成、用户原话或确认。承接的观点与方向或证据冲突时回到对应上游，不擅自换观点再报已确认。

## 自己的正文与双模式

B 额外记录正文身份、路径或所贴全文、版本、完成范围，以及用户允许修改的部分。正文属于原作者、东头自己或其他角色不清时先确认身份，不猜测成稿归属。

完整正文在手时可以独立做 B，不因为没有上游卡而停工：从该稿及用户要求承接当前方向，标明外部事实尚未核验，不伪造第一、二步已完成记录。只有正文片段时可以局部改，但不能检查未取得部分。

## 交给正文与文风环节

A 交接：模式、选择状态、五项作者视角信息、主题与读者、阅读期待、标题状态、主开头及其固定状态、正文问题顺序、依据位置和状态、缺口、用户要求、已选 DNA 或待匹配状态。

B 交接：正文版本、改动范围、沿用的五项作者视角信息、采用标题与开头的状态、实际兑现位置、待补正文及依据、保留要求。已有确认稿单独保留，不将代拟试稿标成确认稿。

同一篇可以按 A → 文风与正文 → B 运行。仅本步工作不自动开启全文写作或发布，也不修改已安装的前两步和总控配置。

标题或开头被用户锁定时原样交接，作者视角在允许修改的部分继续呈现；固定项与观点实质冲突则说明位置，交回上游或总控，不静默覆盖。
