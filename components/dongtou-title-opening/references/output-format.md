# 标题与开头卡、设计记录

正式本步运行默认保存两份独立文件；用户只要对话、局部修改或另有交付要求时优先遵从。使用用户或上游指定的本篇目录；没有指定时沿用当前内容项目的草稿区，可用 `20_drafts/公众号/<本篇>/第三步标题与开头/`。避免把同一篇文件散落多处。

已有同名交付先检查，保留用户确认稿和原版本，新增明确的版本后缀，不覆盖人工定稿。路径和版本必须来自实际保存结果。

## 文件一：标题与开头卡.md

首屏给推荐内容和重要缺口，不把完整思考过程放在前面：

1. **模式与方向：**A、B 或半成稿局部优化；已选方向与 ID、主题范围，若未选写清试做状态。
   沿用五项作者视角信息：**作者视角方式、我的核心观点、为什么这样看、给读者的建议、观点来源与状态**。几句话即可，不新增大表；授权代拟／试稿与用户确认分开，不在正文每段插入待确认标记。
2. **标题：**固定／暂拟／用户已选／授权代选；主标题，按需要给少量备选。固定标题原样列出，不强制多候选。
3. **主开头：**给可直接阅读、由我的发现／看法／选择组织的文字，不仅列写作方法或摘要原作者。固定开头逐字保留并标明；仅要标题时省略开头。
4. **阅读理由与五秒预检：**一句说明为什么值得继续，标明抓手与具体信息；真人试读未做时明确注明。
5. **正文怎样接：**A 列待回答问题和材料位置；B 列实际兑现段落和需要补的地方。对应保留证据状态、条件和缺口。
6. **接下来：**选择状态、待补项、后续文风与正文要求，附详细记录链接。有明确需要才加封面文案，不制作图片。

## 文件二：标题与开头设计记录.md

- 实际读取的文件或所贴文本、路径与版本；区分参考原文、自己的正文、第一步报告与第二步记录。读取范围、缺口和模式选择理由。
- 继承的方向、读者、解释起点、目的、阅读理由、固定标题及其他要求。候选方向不能记成已选。
- 沿用的五项作者视角信息、材料依据与状态；实际询问和回答，或授权代拟的内容及理由。缺字段的旧交接在本步补足就记本步，不伪造上游完成。用户锁定观点、标题或开头的位置和保护方式。
- 设计或诊断的具体问题、备选取舍、主方案理由。B 标出原句与修改范围；不只给泛泛“更有吸引力”。
- 标题和开头的期待 → 支撑材料或实际正文位置 → 事实状态、条件与待补项。把“作者自述”沿用为自述，不变成东头亲测。
- 五秒文字预检、大白话修改，以及实际存在的真人反馈；没有就标未测试，不生成分数。
- 选择状态和交接；原稿、改稿、已确认稿分开定位。只能报告本轮实际完成的阶段。

保存后回读检查两份内容、状态和链接一致，再返回可点击路径。文件写入或读取失败不得说交付已完成。

## 交付前检查

- 模式是否依据自己的正文与用户要求，而不是参考原文长度。
- 上游选择、固定标题和事实条件是否保留；有来源位置可回查。
- A/B 是否沿用同一份我的观点，开头是否让人看见我的判断而不是原文摘要；固定开头也已保护，未把授权代拟冒称用户确认。
- 标题、开头与材料或正文是否匹配；没有编造亲历、效果和新增证据。
- 强五秒是否具体检查，文字预检是否误报为真人验证。
- 用户要的范围、候选数量和正文修改范围是否遵从。
- 两份交付能够被后续文风、正文环节使用；未完成全文或未发布不得报成已完成。
