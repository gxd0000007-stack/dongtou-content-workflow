# 切入点卡与分析记录

默认交付两份文件。用户可直接比较方向，后续写作可回查依据。卡保持简洁，详细推理放记录，不把六个判断强制拆成每个候选的六张表。

## 文件一：切入点卡.md

首屏写清原文主题和本次范围、输入与重要缺口、推荐及理由、选择状态（待选择／用户已选／授权代选），附分析记录链接。

接着用几句话记录本篇五项作者视角信息：**作者视角方式、我的核心观点、为什么这样看、给读者的建议、观点来源与状态**。可自然表达，不新增大表。对话共创沿用用户已说的想法；完整创作授权下直接代写的观点标“授权代拟／试稿”，不能写成用户原话或已确认。候选共用同一观点时只写一次；若候选会改变我的主张，注明差别，选定后保留采用版本。

每项用稳定标识；C0 是原文入口。没有原标题时写“原标题未知；按上游主线概括入口”，不另造所谓原标题。用户已指定标题时原样保留到交接。

C0 只定义入口，不定义叙述者；保留 C0 仍需由我的观点组织内容。

每个候选用几行说明：
- **入口与范围：**一句话说明讲什么，采用全文还是局部，突出与省略什么；方向描述不等于正式标题。
- **给谁看：**当篇读者与已知前提，主要内容需求；必要时补使用阶段。
- **为何愿意看／想让他得到什么：**阅读理由、本篇目的和具体收益；说明理由属于确认信息、真实反馈、原文线索还是工作假设。
- **原文凭什么支持：**位置、支持程度和关键条件，可链接分析记录；不同候选共享依据时可合并说明。
- **怎样讲懂／东头补什么：**必要的术语解释或背景，正文场景的角色，我的解释、判断、建议或真实实践；没有个人故事也可以清楚表达我的看法。
- **缺口与状态：**可讨论／待补材料／暂不采用，理由简写。

优先候选再说明读者能带走的一句话；若有自然的收藏或分享理由就说明，分享的对象与动机标为假设或真实反馈。不要求给每项补转发理由。通常含 C0 共 3–5 项；材料不足时减少，账号不适配时可无候选。

推荐理由需比较原入口：为什么保留或另选，材料支持与读者兴趣是否分别有依据。用户已选或授权代选时记录决定；不因模板再询问一次。

## 文件二：切入点分析记录.md

1. **输入与读取范围：**原文来源、第一步两份报告及底稿路径，本轮实际读了什么；既有报告不代表重新打开原网页。沿用上游未知与缺口。
2. **继承的主题与边界：**引用已有主线与条件，明确全文或局部范围；不重复生成第一步观点表。
3. **当篇编辑判断：**采用的人群卡与用户要求、五项作者视角信息、本篇主要目的、当篇读者的已知前提、主要需求和阅读理由。记录实际问过的缺失关键及用户回答，或授权代拟的依据与试稿状态；不编造对话。区分定位已确认、观点来源状态与兴趣待验证。
4. **候选与材料映射：**各 ID 的入口、突出／省略内容、来源位置与事实状态、承诺能支持到哪一步、正文场景角色、IP 贡献和缺口。
5. **理解与传播检查：**优先候选的术语解释、可复述信息；收藏／分享为何自然或暂不判断。理论只记录实际影响选择的部分，不能代替本篇证据。
6. **取舍、调研与交接：**原入口比较、推荐理由、兴趣待验证点、是否补调研及真实来源日期；未选只保留候选、待判断项及共同约束，不填写“已选方向交接卡”，可作待选择摘要；已选形成交接卡。

## 已选方向交接卡

把以下信息组织成一张简洁卡：选择状态与 ID、五项作者视角信息、原文主题和采用范围、当篇读者及解释起点、本篇目的与阅读理由、已选入口与用户指定标题、阅读收益、正文场景安排、可用依据位置与事实状态、IP 贡献、待补项、必须保留的本篇要求和两份交付路径。作者观点与证据对应到真实材料；没有本人实践则不填造亲测或故事。

选择入口不等于认可文风、确认代拟观点、完成写稿或发布授权。下游依据同一份作者观点与这些约束匹配 DNA、组织内容并写标题与正文；不得在语言简化时抹掉条件、变成客观转述或升级证据状态。
