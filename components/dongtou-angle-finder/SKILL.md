# 东头切入点发现器

从第一步已经读清的内容中，以东头作为作者，决定我想表达什么、为什么这样看、想给读者什么建议。主线是“接住原文 → 我的观点与本篇目的 → 当篇读者与阅读理由 → 比较入口 → 检查材料与理解门槛 → 推荐与交接”。工具介绍、消息解读、能力说明、方法、判断与具体任务都可以成立，不默认把每篇改成痛点教程。

## 输入与范围

- 默认读取第一步的**完整读取记录和速读卡**，沿用其主旨、依据、事实状态、条件和缺口；速读卡用于定位。报告足够时不重新执行观点提炼、不重复制作第一步产物。两个版本冲突时回查详细记录和所指底稿，不拼成新的作者结论。
- 只有链接、标题或零散材料，且不足以确定主题或支撑候选时，交给可用的 dongtou-source-reader 补读，或列出缺口。只有完整记录、缺速读卡时可继续并注明输入状态。不把报告引用写成本轮重新打开原网页。
- 读取 [东头人群与内容需求](references/ip-audience.md)。本篇用户要求优先；用户指定当前项目人群卡时读当前卡，否则默认用此内置可移植快照。记录采用的版本；指定入口不可用时说明并用快照，不搜索无关项目。
- 默认保留原文主题。只取一部分时标明范围；切入方式、文章主题、正文例子分别记录。不得把原文局部功能或自行设想的案例悄悄替换成全文主旨。

## 从第二步开始保留我的视角

第一步继续负责“原文说了什么”。从本步开始，默认用东头第一人称作者视角作创作判断，不能停留在原作者的摘要或客观解读报告。根据本轮意图采用两种方式：

- **对话共创：**用户想先聊、先给自己的想法时，在对话里自然问“我想表达什么、我为什么这样看、我想给读者什么建议”。已有答案直接接住，只问会影响方向的缺失关键；不要求额外填表，不重复询问已提供的观点。
- **直接代写：**完整创作已获授权、用户没有要求先聊时默认采用。读完材料，结合东头定位形成有依据的作者观点，以第一人称组织试稿，继续已授权流程，不逐条等待观点确认。只调用第二步时依然停在切入点交付，不提前写全文。记录中标为“授权代拟／试稿”，不能冒称用户原话或已确认；正文不需要每段标“待确认”。

统一交接五项：**作者视角方式、我的核心观点、为什么这样看、给读者的建议、观点来源与状态**。前三个内容问题可以用几句话自然说清，不新增大表。观点来源分清用户原话／用户确认／授权代拟，以及所依据的原文或其他材料；不由用户确认“定位”推定其已经确认本篇观点。

第一人称用于我的理解、选择、看法和建议，不把原作者的身份、亲历、收入或心理活动移植给东头。没有亲身经历仍可有明确观点；不为显得独立强造反对意见。工具介绍也可以明确“我关注什么、为什么选它、建议怎样用”。保留 C0 是保留原文主题或入口，与作者视角是两个维度：采用 C0 仍须说清我的判断，不能自动退回客观报告。

## 工作流程

1. **接住上游。**引用已有主题与证据边界，确认本篇限制和作者视角方式。原文以介绍或清单为主时沿用内容主线，不强造原作者中心论点；在此基础上组织我的创作判断。
2. **确定我的观点、本篇目的与读者。**接住用户已提供的观点，或按作者视角方式补足“我的核心观点／为什么这样看／给读者的建议”，将我的推断与原文说法分开。选一个主要变化：知道新东西、理解概念、作出判断、开始尝试、纠正用法或进一步使用；按材料保留次要目的。用“当篇身份／已知什么／最想弄明白什么”细化默认的 25–32 岁职场、创业 AI 新手。阶段决定解释起点，年龄不证明兴趣或焦虑。
3. **找阅读理由。**解决问题、了解新东西、学懂方法、作出判断、发现可能性、纠正误解等均可；保留好奇、信息需要与有依据的共鸣。不要求收益一律是省时、省钱或避免损失。区分内容需求、阅读动机与实际工作场景，标明人群兴趣和问题来自用户确认、真实反馈、原文线索还是工作假设。
4. **并排比较入口。**把原文原有入口列为 C0 基准候选；没有原标题时注明未知，按上游主线概括原文入口，不冒称原标题。保留用户已认可或指定的方向；已选且不要求比较时只细化该方向，不强生其他候选。依材料提出少量实质不同入口，如工具、变化、能力、方法、判断或任务；通常含 C0 共 3–5 项，材料少就减少。原入口可以成为首选。每项说清突出什么、弱化什么，以及采用全文或局部。具体场景可作正文示例、论据、边界解释或主切口；建议案例标假设，亲历需有材料。
5. **检查能否兑现与讲懂。**阅读收益能否由已有材料支撑？介绍足够不等于教程足够，知道功能不等于本人验证有效。指出需要解释的术语与必要背景，注明正文中场景的作用。明确东头能补的解释、判断或真实实践。对优先候选用一句话概括读者能带走什么；按需要判断适合阅读、收藏或分享，记录“可能发给谁、为什么”及假设状态，不强造转发价值。
6. **推荐与交接。**结合我的观点、主题保持、材料充分度、阅读理由和理解门槛比较候选，说明原入口保留或不推荐的具体原因，不默认新改法更优。推荐 1–2 项，区分“内容有依据”和“读者兴趣待验证”；状态为可讨论／待补材料／暂不采用。用户未选则待选择，已指定或授权代选就记录选择，无需重复询问。入口选择状态与观点来源状态分别保留，“授权代选”不等于用户确认观点。

常规执行读取 [传播与编辑判断](references/communication-decisions.md)，将理论转为具体判断问题，不要求逐一套满理论。只有需要区分内容需求或判断材料不足时，再读 [按内容类型匹配](references/content-routing.md) 对应部分。六类需求不是封闭分类，符合职场定位的求职等延伸可以成立，不硬贴为 AI 工具教程。

## 依据、个人贡献与调研

- 每个候选绑定原文位置、支持内容、事实状态和关键条件；沿用第一步的作者自述、引用、假设、验证与未知状态。来源链接不是实测证明。
- 作者身份、收入、亲历和产品效果不能移植为东头经历。缺个人案例不阻止透明分析；本篇承诺确实需要测试或案例时列待补。新增解释、推断与用户补充分别归属，不混成作者结论。
- 拓展调研默认按需开启：先指出缺哪个事实、读者问题或案例。涉及当前功能、价格、可用性、规则时按本轮要求核验一手来源并记日期；候选只分析历史报告时不把当时说法升级成当前事实。不为生成入口默认搜索全网热点。
- 不虚构高频提问、匹配百分比、爆款分数或效果保证。原文和账号没有实质关联时交付不适配理由，候选可为空。

## Skill 分工

- dongtou-source-reader 是上游，负责完整读取与观点、依据；仅在关键读取缺口时回到上游。
- 本 Skill 是第二步总控，直接完成传播与编辑判断；不要求另装模块才能使用。
- dbs-spread 可按需辅助检查阅读动机、框架和分享理由；不把其中“情绪优先”等判断变成所有文章的固定要求。用户指令、事实边界与本步目的优先，不让辅助模块改题或另开一套流程。
- dbs-resonate 适合有正文后检查表达，本步不默认调用，不重复抽取原文核心观点。
- DNA 匹配、正式标题、开头和正文交给下游写作。此处的候选一句话是方向描述；用户指定的正式标题原样交接。

## 交付

按 [交付格式](references/output-format.md) 默认保存两份独立文件：**切入点卡.md** 与 **切入点分析记录.md**。卡先给推荐、阅读理由与待验证项，细节留在记录，避免把所有判断堆成每卡的大表。回读两份文件并返回可点击链接。

优先用用户或上游指定目录；东头内容项目可用 10_materials/切入点发现/<本篇>/<明确版本>/。存在不同内容时新增版本。用户只讨论或明确只要对话时不强制保存。

选定后交接五项作者视角信息、主题与采用范围、当篇读者及解释起点、目的与阅读理由、已选入口、阅读收益、正文示例安排、依据与状态、IP 贡献、待补项及用户要求。下游用同一份我的观点组织标题和正文；不是在全文写完后补几个“我”。只调用本步则停在这两份交付，不提前写全文或匹配文风。

## 交付前核对

- 接住上游而未重复第一步；原文主线、局部信息、建议例子可区分。
- 原入口已比较；用户指定的主题和入口保留，改动有理由。
- 我的观点、理由与建议能辨认，作者视角方式与观点来源状态已记录；C0 没有替代作者判断，第一人称没有借用别人经历。
- 候选说明为何值得看、能得到什么；兴趣假设与材料支持分开。
- 阅读目的、解释门槛、证据和正文场景安排相容，介绍没有变成无材料的教程或实测。
- 两份文件、选择状态与下游交接一致；分享假设和理论参考没有写成传播效果证明。
