# 活人感写作接入规则

完整原包位于 `components/human-writing`，源自本机已安装 human-writing 1.0.0，十个文件原样保留，包括 LICENSE、VERSION、agents、references 和检查脚本。内置与独立版的机器标识都是 human-writing。原包默认方法用于本篇表达；创作职责和交接由东头流程负责。

## 哪一步读、怎样用

- 第五步开稿前完整读内置 human-writing/SKILL.md、references/forum-prose.md、references/reality.md，必要形式再读 formats。先检查材料与说话位置，接住第二至四步的观点和采用方案，由原主写手写完整初稿并保存；不提前读详细 revision。
- 第六步是一道独立改稿工序。接住已存在的完整初稿、写作记录、依据和保护范围，再读原入口及相关参考、references/revision.md。按本文适配规则集中改表达，交活人感修订稿和实际改稿记录；不从零另写文章、不重选题、标题、结构或文风。
- 第七步审改完后的当前稿，原五项、三层与至少六轮真实审阅保留。复核作者说话位置、自然中文、材料与亲历来路，以及删除内容是否影响兑现和结构。先前改稿不等于最终质检。
- 整套流程只用内置入口，缺文件报缺，不回退外部同名旧版。单独只做第六步时交修订稿及记录，标待出厂质检；只有指定只检查第七步时可接用户现稿直接审阅，不补造前六步。

## 优先保留什么

当前用户要求和允许修改范围 → 事实与经历边界 → 已定观点、标题开头、正文问题顺序、主结构和主 DNA → 活人感默认表达。

这里的优先级不允许事实造假，也不允许为语言禁令越过用户固定文字。活人感只优化允许范围内的材料展开、句子、解释、衔接与节奏。选定结构的必需功能不能因“少框架、删总结、压缩”被取消。删的是重复，读者需要的答案、条件、行动建议和有用收束仍须兑现。需要改核心承诺交第三步，需要换主结构或主文风交第四步。

不把“无亲历”误解成“作者必须消失”。直接代写授权下可以代拟有依据的第一人称判断，记录试稿状态；“我亲测、查过、咨询过、我的收入/客户/心理”必须有实际材料。引用别人的研究过程也不能写成东头本人经历。不得编深夜、咖啡、房间、对话来制造人味。

## 长稿材料门槛

非虚构新写或大幅重写计划达到 1200 字时，开稿前内部列至少五件不同的具体材料，分别注明用户原话位置或可靠来源，能组成实际过程。五句抽象道理、假设例子、类比和同义推演不算五件材料。字数不足 1200 的稿仍须逐段有新信息和明确来路，不因短就允许伪造。

材料不足先停止长稿。公开事实可查时先定点研究，再重新检查；缺私人经历或判断时最多集中问三个必要问题，不同时交一篇空长稿。用户明确不追问或直接交稿时先研究，再在授权范围内最多写约 600 字短答。固定标题或承诺不能靠缩题兑现时保持待补，不悄悄降低承诺，也不把不能兑现的短答交作合格完整稿。先聊模式仍只问观点。只改现稿一处不重新要求整篇五件材料，只核该处及有关事实，不扩大任务。

材料清单留在写作记录，用户不需要另填表。不凭凑齐五条自动宣布足够，还要判断它们能否托住实际展开。

## 原包检查与保护范围

原脚本只报警、不自动改文，全文结果保留。没有保护项时运行原脚本。用户锁定标题、开头、引用或只许改某段时，调用 components/dongtou-article-writer/scripts/check_human_scope.py，按精确字符区间记录保护文字及用户依据，同时保存原稿全文和可编辑范围两个原脚本结果。

保护文件须匹配当前文章 SHA-256，区间使用 Python 字符位置，准确保留原文、有效范围与依据。未获用户保护的文字不得因难改被豁免。禁止整篇保护后宣布通过。可编辑部分为空、原脚本不能执行或有禁用项未处理，都不能写成“活人感通过”。脚本的语境、节奏提醒要人工判断，形状通过不证明有人味或事实成立。

例子：固定标题含冒号，正文可编辑且已符合要求，则报告“可编辑范围通过；固定标题与原包禁令冲突”。不得说原包对全文已经通过。相同道理适用于局部修改中未获修改许可的原段。

## 交接与验收

第五步记录材料来路、作者说话位置与预读。第六步记录初稿和修订稿路径/指纹、实际读取原包参考、改动前后引句、保留理由、全文/可编辑范围结果及保护冲突；使用 [改稿记录模板](../components/dongtou-wechat-writing/assets/human-writing-record.md)。第七步对当前修订稿重新核查并保存 human_writing 采用记录，格式见 [第七步回执说明](../components/dongtou-article-review/references/human-writing-receipt.md)。继承记录与本轮实际执行分开，不把旧稿多复制一次当独立改稿。

最后总控运行 verify-delivery 时同时要求作者视角与活人感记录。旧回执可用旧格式核对历史一致性，不能声称做过新增检查。五项标准未通过、作者视角失败、材料不足或活人感可编辑范围未通过时不能判可交稿。用户明确保护范围的冲突可记录为范围受限，但五项与适用作者视角仍须通过；报告具体说明限制，绝不写“全文语言禁令清零”。终检后改字必须补相关检查和当前全文终检，到文案与质检报告结束。
